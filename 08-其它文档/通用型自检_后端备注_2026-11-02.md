# 通用型自检 · 后端备注 · 2026-11-02

> 视角：API / 数据 / 部署。问题：换一家企业部署时，缺什么才能「开箱可配」。  
> 证据分档：【实测】代码/Compose · 【文档口径】契约/选型/状态 · 【推断】由前两者推出。  
> 未代启服务；未读 `.env` 密钥（仅对照 `.env.example` 键名）。  
> 与 `当前状态.md` / tracker 交叉：不重复产品空话，只列换企业缺口。

## 结论先行

当前形态是 **单组织单实例 MVP**：一部署 ≈ 一个逻辑租户（整库 + 默认单 Qdrant collection）。  
**同实例无法安全服务两家企业**（文档明确不做多租户，代码无 `org_id`/`tenant_id`/`shop_id`）。  
换企业可行路径：**新库 + 新 collection 名 + 新 JWT/管理员密码 + 新 `.env`**，不是改一个租户开关。

开箱可配还缺（按致命度）：生产密钥强制改 · 成员除 bootstrap 外无创建 API · Compose `web` 非真实前端 · 无迁移工具 · SSE 501 · 向量/静默 memory 回退需运维知情。

## 3. 文档 / 向量隔离

**DB：** 文档与块挂 `kb_id`；会话挂 `user_id`。无企业维。

**Qdrant：**

| 项 | 现状 | 档 |
| --- | --- | --- |
| 集合 | 默认名单 collection：`enterprise_rag_chunks`（`QDRANT_COLLECTION`） | 实测：`app/config.py`、`.env.example`；选型：单 collection + `kb_id` filter |
| payload | `kb_id, doc_id, chunk_id, chunk_index, text[:500], is_archived` | 实测：`indexing_service.py` |
| 检索过滤 | `kb_id` + `is_archived=False`；删除按 `doc_id` | 实测：`vector_store.py` |
| stub / 回退 | `EMBEDDING_STUB` 或无 key → 进程内 memory；Qdrant 不可达时 **静默回退 memory** | 实测：`vector_store.py` |

【推断】多企业共一台 Qdrant 必须改 collection 名并分库；否则向量串。静默 memory 回退会让「库挂了仍像能问答」，重启丢向量——换企业运维必须知情。

## 4. 配置项清单（换企业必过）

来自 Settings（`app/config.py`，pydantic-settings）+ `.env.example` Compose 键：

| 类别 | 键 | 换企业注意 |
| --- | --- | --- |
| 库 | `DATABASE_URL`；Compose 另有 `POSTGRES_USER/PASSWORD/DB` | 每企业独立库；禁共用未改密码默认值 |
| 向量 | `QDRANT_URL` · `QDRANT_COLLECTION` | 每企业独立 collection 名 |
| Embedding | `EMBEDDING_BASE_URL/API_KEY/MODEL/DIM` · `EMBEDDING_STUB` | 无外网 key 时显式 stub 或自建 endpoint |
| LLM | `LLM_BASE_URL/API_KEY/MODEL` · `LLM_STUB` | 同上 |
| 鉴权 | `JWT_SECRET` · `JWT_ALGORITHM`(代码默认 HS256，example 未列) · access/refresh 过期 | **生产必须改 secret** |
| 管理员 | `BOOTSTRAP_ADMIN_USER/PASSWORD/DISPLAY_NAME` | **禁止保留 changeme** |
| 上传/切片 | `UPLOAD_DIR` · `MAX_UPLOAD_MB` · `CHUNK_SIZE/OVERLAP` | 路径与配额按机盘 |
| 杂项 | `APP_VERSION`；Compose `API_PORT`/`WEB_PORT` | 端口冲突时改 |

Stub：`true|false|auto`；auto = 无 API key 则 stub（`config.py`）。

DB 初始化：`Base.metadata.create_all`（`database.py`），**非 migration**。

## 5. Compose 缺口

| 期望 / 需要 | 现状 | 档 |

## 7. 换企业再部署 · 检查单（后端）

- [ ] 独立 `DATABASE_URL` / Postgres 库与密码（非 changeme）
- [ ] 独立 `QDRANT_COLLECTION`（及是否共用 Qdrant 集群）
- [ ] 新 `JWT_SECRET` + `BOOTSTRAP_ADMIN_PASSWORD`
- [ ] Embedding/LLM：真实 key 或显式 stub / 自建 base_url
- [ ] CORS：当前 `allow_origins=["*"]` + `allow_credentials=True`（`main.py`）——上线应收紧到企业前端域
- [ ] 成员策略：仅 bootstrap，或补创建成员 API / 运维插库流程
- [ ] 知悉：无 Alembic；schema 靠 `create_all`
- [ ] 知悉：Qdrant 挂了可能静默 memory；SSE 501；web compose 非真前端
- [ ] 前端：Vite/`enterprise-rag-web` 或替换 compose web 镜像（前端班组）

**非问题：** 未见写死某客户 org/shop 字符串；产品名通用。障碍是 **缺租户维 + 运维默认值 + 若干 MVP 缺口**，不是绑死一家公司。
